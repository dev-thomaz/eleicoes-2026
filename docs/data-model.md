# Data model

## Current implementation

The runtime data model is defined in `src/features/election/types.ts` and generated by `scripts/election/generate-data.mjs`.

The model is centered on a two-candidate presidential comparison. It does not model the full candidate field of the election.

## Core unions

### `CandidateKey`

```ts
type CandidateKey = "lula" | "flavio";
```

Purpose: stable application key for the two compared candidates.

Used by:

- result records;
- colors;
- labels;
- filters;
- leader counts;
- ranking calculations;
- map coloring.

### `Region`

```ts
type Region =
  | "norte"
  | "nordeste"
  | "centro-oeste"
  | "sudeste"
  | "sul";
```

Purpose: client-side regional grouping derived from UF constants.

### `ViewLevel`

```ts
type ViewLevel = "states" | "detailed" | "municipalities";
```

Purpose: controls map mode.

- `states`: state-level choropleth.
- `detailed`: national municipality-level choropleth.
- `municipalities`: municipality map scoped to a UF.

### `LeaderFilter`

```ts
type LeaderFilter = CandidateKey | "all";
```

Purpose: filter by comparative leader or show all leaders.

## Candidate identity

`CandidateIdentity` stores identifiers from TSE result files:

- application key;
- election ID;
- office code;
- candidate number;
- candidate sequence;
- full name;
- ballot name;
- party acronym.

The current generated metadata includes identities for:

- Lula: number `13`, sequence `280002542548`, party `PT`;
- Flávio Bolsonaro: number `22`, sequence `280002551544`, party `PL`.

## Candidate result

`CandidateResult` stores:

- `candidateSequence`;
- `candidateNumber`;
- `votes`;
- `percentage`.

Percentages are parsed from TSE fields in the ingestion script.

## Shared comparison result

`ComparedResult` is embedded in both state and municipality results:

```ts
interface ComparedResult {
  results: Record<CandidateKey, CandidateResult>;
  leader: CandidateKey;
  marginPercentagePoints: number;
}
```

Derived fields:

- `leader`: candidate with more votes in the two-candidate comparison. Ties currently resolve to `lula` because the comparison uses `>=`.
- `marginPercentagePoints`: absolute difference between the two candidate percentages.

Map-specific display rule:

- if the displayed margin rounds to `0,00 p.p.`, the map uses neutral gray while keeping hover/click enabled.

## State result

`StateResult` represents a UF-level comparison.

Identifier:

- `ibgeCode` for geographic matching;
- `uf` for display and user interaction.

Main fields:

- `uf`;
- `ibgeCode`;
- `name`;
- `region`;
- `municipalitiesCount`;
- `results`;
- `leader`;
- `marginPercentagePoints`;
- `sourceGeneratedAt`;
- `aggregationStatus`.

Used by:

- state map mode;
- metric cards;
- details panel;
- state filter options.

## Municipality result

`MunicipalityResult` represents a municipality-level comparison.

Identifier:

- `ibgeCode` is the primary runtime/geographic ID;
- `tseCode` is retained for traceability to TSE municipality result URLs;
- `id` duplicates `ibgeCode` in the generated data.

Main fields:

- `id`;
- `ibgeCode`;
- `tseCode`;
- `name`;
- `uf`;
- `region`;
- `results`;
- `leader`;
- `marginPercentagePoints`;
- `sourceGeneratedAt`;
- `aggregationStatus`.

Used by:

- municipality maps;
- detailed national municipality map;
- table;
- rankings;
- details panel;
- search;
- capital highlighting.

## Election metadata

`ElectionMetadata` describes the generated dataset:

- generation timestamp from TSE;
- app generation timestamp;
- source (`tse-divulgacao`);
- environment (`oficial`);
- cycle;
- election ID;
- office code/name;
- turn;
- aggregation status;
- source URLs;
- candidate identities;
- summary counts and warnings.

Current generated summary:

- 27 states;
- 5,571 municipalities;
- 0 failed municipalities.

## Municipality dataset wrapper

`MunicipalityDataset` wraps the municipality index:

- small metadata subset;
- `municipalities` array.

## Electorate profile

`ElectorateProfile` represents the generated demographic electorate summary for one municipality.

Identifier fields:

- `ibgeCode`, used to join with `MunicipalityResult`;
- `tseCode`, retained for traceability to TSE electorate/result sources;
- `uf`;
- `region`.

Aggregate fields:

- `total`;
- `byGender`;
- `byAge`;
- `byEducation`.

The frontend currently uses:

- `total`;
- `byGender`;
- `byAge`.

The education bucket is generated and kept for future analysis, but is not yet displayed in the dashboard.

The electorate profile data supports territorial demographic charts only. It does not identify the profile of voters who chose a specific candidate.

## Electorate profile dataset wrapper

`ElectorateProfileDataset` wraps:

- metadata about the TSE electorate source URL;
- source generation timestamp;
- app generation timestamp;
- number of generated profiles;
- unmatched row count;
- normalization metadata;
- `profiles` array.

## Filter state

`FilterState` mirrors URL query state:

- `level`;
- `region`;
- `uf`;
- `leader`;
- `municipality`;
- `query`.

## Constants

`src/features/election/constants.ts` provides:

- candidate labels;
- candidate colors;
- capital names by UF;
- region labels;
- UF to region mapping;
- UF to IBGE state code mapping;
- ordered UF list.

## Relationships

```text
ElectionMetadata
      |
      +--> CandidateIdentity by CandidateKey

StateResult
      |
      +--> ComparedResult
      +--> UF
      +--> IBGE state code

MunicipalityResult
      |
      +--> ComparedResult
      +--> TSE municipality code
      +--> IBGE municipality code
      +--> UF

ElectorateProfile
      |
      +--> TSE municipality code
      +--> IBGE municipality code
      +--> demographic buckets
```

## Future considerations

- Add schemas for generated JSON validation.
- Represent neutral/tied displayed margins explicitly instead of deriving it in the map component.
- Generalize candidate comparisons beyond the hard-coded `lula`/`flavio` union.
- Add total compared votes if needed for future table or tooltip analysis.
- Add richer demographic buckets such as education, race/color, and disability where they support a clear product question.
